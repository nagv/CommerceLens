# CommerceLens Services Implementation Plan

> Execute with superpowers:subagent-driven-development. User has authorized implementation.

**Goal:** Six runnable polyglot services with a customer/operations UI, PostgreSQL persistence, HTTP provider boundaries, asynchronous notifications, and reproducible integration tests.
**Architecture:** Independent sibling Git repositories; central Docker Compose. Order service orchestrates reservation, payment and shipment; confirmed orders enter a durable outbox published to RabbitMQ. Notification consumer sends email through an HTTP mock provider. All amounts are integer USD cents. Local-only demonstration, no public production deployment.
**Spec:** ../../../README.md (CommerceLens project scope; service implementation is this milestone; RAG/chat ingestion follows separately).

## Shared contracts

All JSON uses camelCase. IDs strings. Errors JSON with message. Health GET /health returns {status:"ok"}; services listen 8080 except portal 80 and payment/worker 8080. Services use /api prefixes below.

- Inventory GET /api/products returns array {sku,name,priceCents,available}. Seed BOOK-001 (Agentic Systems Handbook, 2900, 100), KIT-001 (Developer Desk Kit, 4900, 50), MUG-001 (CommerceLens Mug, 1500, 100).
- Inventory POST /api/reservations {orderId,items:[{sku,quantity}]} -> {orderId,items:[{sku,name,quantity,priceCents}],subtotalCents,status:"reserved"}. Idempotent same order/payload; conflicting replay 409. Atomic stock checks, positive quantities, duplicates normalized or rejected. POST /api/reservations/{orderId}/release -> {status:"released"}; repeated release no extra stock.
- Payment POST /api/payments {orderId,amountCents,currency:"USD",scenario:"success"|"decline"|"timeout"} -> {paymentId,status:"authorized"}. POST /api/payments/{paymentId}/refund {orderId} -> {status:"refunded"}. Explicit failure status 402 declined, 504 timeout. Provider URL env PAYMENT_PROVIDER_URL (base URL), connect HTTP to /payments and /refunds. Idempotency key orderId.
- Shipping POST /api/shipments {orderId,postalCode,scenario:"success"|"failure"} -> {shipmentId,status:"created",trackingNumber,shippingCents:500}. Env SHIPPING_PROVIDER_URL base; provider /shipments. GET /api/shipping/rate -> {shippingCents:500,currency:"USD"}.
- Order GET /api/products proxies inventory. POST /api/orders body {customerEmail,postalCode,items:[{sku,quantity}],paymentScenario:"success"|"decline"|"timeout",shippingScenario:"success"|"failure"}, required Idempotency-Key header. Validate email/postal/items. Total = authoritative inventory subtotal + 500. Return full order {id,status,customerEmail,postalCode,items,subtotalCents,shippingCents,totalCents,paymentId,trackingNumber,failureReason,createdAt}; POST 201 confirmed or clear 4xx/5xx with saved failed order, GET /api/orders and /api/orders/{id} expose it. Persist pending before external work, reject concurrent key conflicts, never double-charge replays. Explicit uncertain payment outcomes marked payment_unknown; do not treat timeout as definite decline. Compensate stock and authorized payment on definite subsequent shipment failure; surface compensation failure as manual_review. HTTP deadlines and bounded behavior.
- RabbitMQ durable queue order.confirmed; JSON {eventId,orderId,customerEmail,totalCents,trackingNumber}. Order uses durable PostgreSQL outbox with publish confirms and delivery retry. Worker acknowledges only after durable delivery outcome; dedup by eventId via PostgreSQL. Three bounded email attempts then dead-letter queue order.confirmed.dead. HTTP EMAIL_PROVIDER_URL base /email payload same event. Worker GET /api/notifications returns array {eventId,orderId,status,attempts,lastError}; GET /health.
- Mock provider central: POST /payments {orderId,amountCents,currency,scenario}, /refunds {paymentId,orderId}, /shipments {orderId,postalCode,scenario}, /email {eventId,orderId,customerEmail,...}. Stable IDs/idempotency, scenario failures, no credentials needed; label mock in UI/docs. Email mock fail with recipient containing fail-email.
- Portal same origin proxies /api/orders, /api/products to order; /api/notifications to worker via nginx. Product catalog/cart, quantity editing, checkout with email/postal, scenario selection, confirmation/order history/details, notification status and errors, refresh. Do not present a fake working AI chat; show future assistant clearly unavailable if included.

## Tasks and ownership

Integration ruling: mock shipment scenario=failure is a definitive HTTP422 rejection. Real upstream 5xx/timeouts are uncertain and must lead to manual review rather than automatic compensation assumptions. Notification terminal failure state is dead, attempts=3.

- [x] Backend worker: order + inventory repositories. Write behavior tests first, implement services/Dockerfiles/docs, compile/test and report results.
- [x] Integration worker: payment + shipping + notification repositories. Write failure/idempotency tests first; implement clients/worker/Dockerfiles/docs and report verification.
- [x] UI worker: portal repository. Test cart totals/validation, build accessible working UI, Dockerfile/nginx, lockfile and README.
- [x] Controller: central mock providers, Compose, bootstrap, smoke tests and generic OpenWiki/Graphify instruction/exclusion templates; run complete workflow.
- [x] Independent review: inspect contracts, compensation, concurrency, retry bounds, UI integration; fix important findings and repeat affected tests.
- [x] Commit/push implementation to requested repositories after validation. Report actual verification limits.

## Review focus

Concurrent stock reservations must not oversell; checkout retries must not charge twice; timeout must not imply no charge; shipping failures must release/refund or mark manual review; email failure must not undo confirmed checkout. Reject invalid input and prevent UI injection. Defaults bind exposed ports to loopback; credentials in local env only. Preserve tests, schemas, configuration examples, and source directories in graph extraction. Documentation generation order is Graphify then OpenWiki; do not generate pretend artifacts.
